# FormSoftware interface

## Direction

A contemporary record workspace with the precision of a terminal: boxy, quiet, typographic, and tactile. The original sketch establishes left-hand navigation and a large table canvas. Extend that structure with a right-hand inspector, compact view controls, and visible save/error states.

## Visual system

Use the tokens in `web/src/styles/tokens.css` as the source of truth. Warm paper `#faf9f5`, canvas `#f5f4ef`, olive-neutral sidebar `#efeee7`, dark ink `#292c29`, and restrained vermilion `#cc4c31`. Colors for relation tags are muted and secondary to their text labels. Focus carries an accent. Grid cell selection uses ink instead (a 2px ink ring on the active cell and an olive `#e9ecdf` wash on a range), so it never reads as an error. No status depends only on color.

The brand mark (`BrandMark`) is always vermilion (`--accent`) in the sidebar, boot screen, and login screen. `web/public/favicon.svg` uses the same vermilion fill with `#fffaf0` strokes. The favicon cannot read CSS tokens, so keep its hard-coded fill equal to `--accent`.

IBM Plex Sans supports titles and record text. IBM Plex Mono supports metadata, dates, durations, counts, and keyboard hints. Fonts are self-hosted. Square corners, one-pixel rules, flat surfaces, and limited elevation define panels. Avoid terminal raster effects, glowing text, ornamental gradients, and decorative fake controls.

## Layout and interaction

- A 228px sidebar holds forms, explicit option-list management under Configuration, and account controls. On small screens it becomes an icon rail.
- The top bar shows workspace context and connection state. The form heading names the collection and offers Import and New record.
- The table panel contains a view selector, filters, sorting, grouping, column controls, and search. A simple footer reports the filtered count and the total duration of the loaded rows.
- The grid loads every row of the view (up to 5,000) instead of paging; it fetches 500 rows per request and shows the first request's rows while a new query finishes. Refreshes replace the rows at once, so scroll position and cell selection survive saves. Only rows near the viewport are rendered; the selected cell's row and any row being edited stay mounted while scrolled away, so keyboard focus survives. Over 5,000 rows, the footer says how many are shown and suggests a filter. A saved view can turn on Open at the last row, which scrolls to the end once when the view opens; it does not select a cell, so typing does not edit the last row by accident.
- The grid follows Airtable's select-first model. A click selects a cell; clicking the selected cell again, Enter, or F2 edits it, and typing a character starts editing a text or number cell with that character (other types open their editor). Clicking another cell while editing saves the edit, then selects that cell without editing it.
- Arrow keys move the selection, and Cmd/Ctrl+Arrow jumps to the row or column edge. Shift+click, Shift+Arrow, and dragging select a rectangular range. Clicking a column heading selects that column's visible cells, and its chevron or a right-click opens the column menu. Cmd/Ctrl+A selects every visible cell. Escape collapses a range to its anchor cell, and on a single cell clears the selection so workspace shortcuts (`/`, `N`, `?`) work again; while a cell is selected, typed characters go to that cell. Tab and Shift+Tab move along the row and leave the grid at its edges. Navigation skips collapsed groups and includes an unsaved draft row.
- Editors align with the cell; notes, relations, and files expand into compact anchored controls. Enter or clicking away saves; Escape cancels and keeps the cell selected. Tab saves and selects the next cell; Cmd/Ctrl+Enter saves a note. Failed saves retain the draft. Keyboard focus for the selected cell sits in a hidden text field, so an input method (for example Chinese Pinyin) composes in place over the cell and the editor opens with the committed text.
- Cmd/Ctrl+C, X, and V copy, cut, and paste the selected range as tab-separated text plus a private in-grid format that keeps stored values, so links and options paste losslessly between fields of the same type and target. Copies use plain values (ISO dates, unformatted numbers, link names, durations such as 1h 30m); pasted text accepts those and the grid's display formats. Link names resolve by exact Name on the server; a missing or ambiguous name refuses the paste. One copied value fills a larger selection; a block repeats to fill a selection that is at least as large; otherwise the block pastes from the selection's top-left cell, drops columns past the last field, and selects the pasted range. A paste past the last row shows a confirmation strip before adding rows below the table. A cut outlines its cells (dashed ink) and clears them in the same save as the paste. Delete or Backspace clears the range. Files are never written by paste or clear, and required fields are never emptied; a notice says when cells were skipped. Every paste or clear saves atomically through the batch endpoint and is refused entirely if any record fails validation or changed elsewhere, with a notice naming up to three rows. Pastes and clears are limited to 500 records; copying more shows that limit.
- Space opens the selected cell's record in the record editor (not on the draft row).
- A small ink square at the selection's bottom-right corner is the fill handle. Dragging it up or down over rows (never across columns, as in Airtable) previews the target cells with a dashed outline and, on release, copies the selected rows into them, repeating a multi-row block; filling upward repeats from the bottom, so the adjacent row matches the nearest source row. Cmd/Ctrl+D fills down: a taller selection copies its top row into the rest, and a single row copies the row above. Fills use stored values (links and options need no lookups), skip files and empty required values, write only cells that change, never add rows, and save atomically like a paste, at most 500 records. The handle hides while editing or while a draft or the record editor blocks grid writes.
- Cmd/Ctrl+Z undoes and Shift+Cmd/Ctrl+Z (or Ctrl+Y) redoes changes: cell edits, pastes, cuts, clears, fills, saved draft rows, duplicates, deletes, and record editor saves, creates, and archives. History is per form, keeps 50 steps, pauses while the record editor is open, and is lost on reload; a new change clears redo. Each step replays atomically with the versions it left behind, so if any of its records changed since (another tab, an attachment change, a refresh), the step is refused with a notice and dropped, and older steps still work. Undoing a delete restores the records in their original position; undoing a new row archives it. Text fields, including the inline cell editor and search, keep their own Cmd/Ctrl+Z. Schema changes and attachment changes are not in the history. A step that cannot be recorded is left out without failing its save.
- Field creation offers Number (whole/decimal precision, plain/currency/percent display), Rating (1–10 maximum, five icon styles and muted colors), Single select, Multiple select, and Link to another record alongside the basic types. Both field-creation entry points share settings. Select presets use reusable option lists under Configuration; links can target any available form, including the current form. Storage types remain fixed after creation; numeric display and rating settings are editable from the column menu. Ratings support click and arrow/Home/End keyboard input, an explicit zero, and clearing optional values.
- A + button after the last visible column opens the field dialog. New fields appear immediately to its left and remain visible after reload, including beyond six columns and when all previous fields are hidden. Only explicit visibility settings hide columns.
- A column heading's chevron button or a right-click opens a compact action menu; clicking the heading itself selects the column. It provides first-column freeze, field editing, linked-form navigation for relations plus separate field settings, duplication, positional insertion, descriptions, sorting, filtering, grouping, hiding, and confirmed archival. The primary Name field cannot be archived.
- The first visible data column and row-number gutter freeze by default. Freeze and grouping are saved view settings; other columns cannot be individually frozen. Descriptions appear as header tooltips and field help in the full record editor.
- Drag a column boundary to preview its width; release to autosave to the active view. Escape or pointer cancellation restores the original width. Focused resize separators support Left/Right (10px), Shift+Left/Right (50px), and Home/End (100/800px). Numeric width inputs save on blur or Enter. Width writes are queued, and failures keep the visible width with a Retry action. Resizing does not reload records, move the scroll position, or save unrelated pending view adjustments.
- A summary bar stays pinned under the grid. Each column's cell offers a summary (shown as Summarize on hover until one is chosen): Sum, Average, Min, and Max for numbers and durations; Earliest and Latest for dates; Checked, Unchecked, and Percent checked for checkboxes; Filled, Empty, Percent filled, and Unique for the rest (files offer only the first three). Summaries cover every loaded row of the view (up to the 5,000-row load limit), keep decimals exact, and show durations as hours and minutes. Grouped views repeat each column's summary in the group headings for that group's loaded rows, except the first column, which holds the group name. The choice is a column setting saved with the view like visibility; the server refuses a summary that does not fit the field type.
- Grouping is one level across the filtered collection, ordered on the server. Headers show full group counts, plus the loaded portion when a view exceeds the load limit. Multi-record relations group by the complete set of links; attachment fields group by file count. Group collapse is transient and scoped to displayed rows. The Group control clears grouping.
- Relation search offers Add option / Add record only after a successful search returns no results for the current nonblank query. The action creates a linked record and selects it; the cell still follows its normal save/cancel behavior. Additional required fields must be completed in the linked form. Creation blocks the parent editor until the request finishes.
- Right-click a row (or Shift+F10 on a focused cell) for Open Editor, Insert record above/below, Duplicate record, and Delete record. The explicit editor is docked on the right; on narrow screens it fills the table panel.
- Hovering a row number reveals its checkbox. Checked boxes remain visible; the header checkbox selects all loaded rows. A selection strip offers count, clear, and confirmed deletion. Deleting is all-or-nothing and limited to 500 records at a time; it can be undone.
- Relative insertion starts an inline draft with required fields reachable, then explicitly saves a validated record. Add a record below the table appends the same kind of empty draft row at the end and selects its first cell, so typing or pasting starts there; N and New record still open the record editor. A paste onto the appended row creates records directly (the row's own values fill gaps in the first one) and asks only for rows beyond it. Default manual order persists across reloads. Explicit sorts and filters still determine visibility and placement after saving.
- Inspector edits require an explicit save and confirm unsaved navigation. Inline conflicts retain the entered value and offer an explicit discard/load-latest action. Draft rows block leaving the form until saved or canceled. No stale write is silently retried.
- Toolbar and column filters share a wide dialog with compact Where/And → Field → Operator → Value rows, inset controls, and a padded action footer. Rows stack on mobile. Choice popups use viewport-constrained fixed positioning, adapt above/below the control, scroll internally, and focus search without scrolling the dialog. Conditions combine with AND; applying commits the draft, closing cancels it, and Clear removes all conditions.
- Relation filters offer is, is not, is any of, is none of, is empty, and is not empty. Searchable choices support removable selections and up to 100 records for any/none; searches include disabled options for historical records. For multi-link fields, is means includes. Negative filters include empty cells; add is not empty to exclude them. Empty checks hide the value control. Filtering is manual, with no AI controls or linked-record creation.
- The form designer’s Add a field section supports optional descriptions and shows existing descriptions in its field list.
- New form, schema design, CSV import, and keyboard help use native modal dialogs. Dangerous record/field/form/attachment operations ask for confirmation in context.
- `/` focuses search, `N` creates a record, Escape closes a panel, and Cmd/Ctrl+Enter saves the inspector. Shortcuts yield to text inputs and dialogs.

## Components

Keep controls small but legible, with visible keyboard focus and labels. Table rows are 47px. Table and inspector headers share the 38px `--grid-header-height` token so their bottom borders align. Primary record titles are readable sans-serif. Numerical values align right. Use shared buttons, errors, dialogs, and popovers; feature components own their domain presentation. The native skeleton uses the same colors and geometry with platform typography.
